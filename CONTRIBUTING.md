# Contributing to VECTRA

Thank you for your interest in VECTRA. The project is at an early concept and architecture-research stage, so thoughtful feedback is valuable.

## Before contributing

1. Read the project [README](README.md) and relevant documents in `docs/`.
2. Search existing issues and discussions before opening a new one.
3. For substantial changes, open an issue or discussion first so the scope can be agreed.
4. Do not submit code copied from another project unless its origin and license are clearly identified and compatible.

## Current contribution priorities

- Review the project scope and identify missing requirements.
- Provide constructive feedback on architecture proposals.
- Identify security, privacy, accessibility, and maintainability risks.
- Improve documentation for clarity and technical accuracy.

## Pull requests

- Keep changes focused and explain their motivation.
- Link related issues or discussions.
- Include tests for code changes once executable code exists.
- Document assumptions, limitations, and any third-party dependencies.
- Do not claim that an unimplemented feature works.

## Licensing

A component-specific licensing policy is being prepared. Do not submit code unless you have the right to contribute it and agree to the license terms that will apply to that component. The project will publish clear contribution and licensing terms before accepting substantial code contributions.

## Code of conduct

By participating, you agree to follow [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
